# FiveMinuteMore AI 开发工作流

2026-10-26 更新。根规则见 [AGENTS.md](../../AGENTS.md)，项目事实和历史决策见 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)。本文件描述执行约定，不代表 AionUi 提供不可绕过的权限锁。

## 1. 每个新会话的入口

以 `E:\GameProjects\FiveMinuteMore` 或已确认的独立 Worktree 为工作区；先读根 AGENTS，再按任务读本文件及 PROJECT_CONTEXT 的相关段落。不要每次重扫所有历史聊天或全工程。核对当前 HEAD/分支、工作树状态、未跟踪文件、已有 Worktree 与适用的子目录 AGENTS。
新会话可以明确要求：“先读取 AGENTS.md、docs/ai/PROJECT_CONTEXT.md、docs/ai/WORKFLOW.md，核对当前工作树后执行。”AionUi 的持久助手规则也应包含这三个入口；保存规则只对新建会话生效，不能当作当前运行时已经重载的证据。

## 2. 调度判断：默认一个执行者

Codex 是唯一默认主管，负责需求理解、一次必要规划、接口与所有权、关键架构/核心视觉、集中验收和返工决策。普通编程、调试、测试不由主管逐步代写。

- **默认 Antigravity**：小任务、单一功能/模块、高度耦合、需频繁协调，或拆分成本高于收益时，完整交给 Antigravity。即使任务大也不强行并行，此时不调用 CodeBuddy。
- **按需 Antigravity + CodeBuddy**：只有存在两个独立目标、文件/模块边界清楚、接口可提前定、无必须串行的开发依赖，且节省时间大于规划/通信/整合/冲突成本时拆分。两者都可实际开发 UI、玩法、系统、工具和测试，不把 CodeBuddy 限定为审查员。
- **Cursor 备用**：只在默认调度下，执行者无法完成、额度/工具失败或最多两轮自主修复仍不通过时考虑。不能因其可用而额外调用；接管前原写入者必须停止。
- 禁止自动接入 WorkBuddy、OpenCode 或其他未经授权 AI；CodeBuddy 是本团队的第二开发者，与二者不同。

关键设计可以由 Codex 亲自负责判断和方案；具体视觉代码仍可委派。若用户明确要求 Codex 自己实现，按用户授权执行。

## 3. 一次性任务契约

先调查现有系统，再只澄清真正影响方案的缺口。用户限定分析/暂不实现时不写代码；已明确授权的常规工作不重复访谈。核心视觉样板先提交实际 Camera 结果，经用户确认再推广。

任务板每项必须包含：

1. 目标、非目标、执行模式（默认/指定 Agent）与执行者。
2. 正式来源和独立 Worktree/工作目录、允许修改的精确文件/资源、公共接口与禁止触碰内容。
3. 可验证验收标准、必要编译/测试命令、视觉或性能证据范围。
4. 最多两轮自主修复、允许提前升级的重大阻塞、最终报告路径/格式。
5. 并行时的前置产物和最终合并通知责任，不让两个 Agent 同改公共文件。

AionUi 协调只用 team_* MCP。需要了解实际状态时读取 team_members、team_read_messages、team_task_list；用真实 slot_id 分派。team_task_create 的 owner 会自动通知/唤醒，不再额外发一条“开始干活”。后续 team_send_message 仅用于具体上下文、集中返工或必要状态传递。
若单次参数/权限失败，先用 bundled aioncore 的 `team capabilities` / `team help` 核对；MCP 不可用时按该契约走 Team CLI，不猜接口、不绕用其他代理工具。不要在持久文档中写死当前 slot_id。

## 4. Worktree 与代码安全

- 分派前核对 `git status --porcelain=v1`、`git rev-parse HEAD`、分支和 `git worktree list`，保留现有 dirty 文件。不要将旧报告“干净”视为当前状态。
- 优先每位执行者独立 Worktree，记录基线 HEAD。Worktree 默认不含正式工作树未提交修改；若任务依赖这些修改，必须先设计受控快照/补丁方案，不能静默遗漏或覆盖。
- 本轮三份 AI 文档尚未提交；从旧 HEAD 新建的 Worktree 不会自动包含它们。准备任务时将最新 AI 文档作为有记录的受控快照带入，或明确要求先读正式目录的这三份文件；不要把历史 Worktree 的旧 AGENTS 当作已经更新，也不要为此自动提交或覆盖运行时代码。
- 工具不能提供隔离时，严格划分文件/资源。任一共享接口只有一位写入者；发现冲突就停相关修改并报告，不同时抢修。
- 不擅自 reset --hard、危险删除、清理 Worktree、提交、合并主分支或部署。对已有 Worktree 的工具成果先核对状态/哈希再决定是否整合。
- 未指定的战斗/美术/地图规则保留；清理需要静态、动态和共享引用证明，不能把 Node2D 或“未引用”直接等同废弃。

## 5. 成员自主执行与一次终报

执行者独立完成代码阅读、实现、编译、测试、调试及必要回归，在自身会话最多两轮自主修复。普通失败不发主管、不在每次错误后请求重规划。只有重大架构/文件冲突、无法解决的阻塞或用户必须作决定时提前升级。
修复轮数随任务累计记录，不能因新会话轮次、重建执行者或主管退回而清零；达到上限后报告真实状态，再按执行模式决定接管或阻塞。
完成整项后一次提交精简终报：实际 Agent、任务ID、工作树/基线、修改文件、功能、实际测试命令/退出码/数量、修复轮数、未解决项和证据路径。不要用“应该通过”或只有文字自述代替结果。
开发任务可保持 in_progress 并在 description 写最终 HANDOFF_READY/RESULT/报告路径；Codex 读取实际交付后才 completed。无工作不唤醒成员，不因 idle 自动判定失败。

### 单执行者

Antigravity 全部完成后一次通知 Codex。不是用户“指定 Antigravity”的严格模式，只是默认不值得拆分的普通任务，仍由 Codex 集中验收。

### 两个并行执行者：合并终报

沿用已验证的低频机制，而非反复进度通知：

1. Antigravity 最终写报告/任务就绪标记，只向 CodeBuddy 发一次最终就绪消息。
2. CodeBuddy 自己完成后读两项本轮任务；均就绪时先写本轮 LEAD_NOTIFIED 标记，再向 Codex 发一次合并通知，带两份报告路径即可，不审查或重跑对方代码。
3. CodeBuddy 若先完成而另一项未就绪，立即结束会话轮次并 idle；后续 Antigravity 的就绪消息再唤醒它，只做通知转发。不得开流等待、循环问询或持续占用模型流。
4. 若主管集中退回，两项本轮就绪标记与通知标记须重置/明确版本，不能读取到旧报告就误判完成。每轮只合并一次。

任务有开发依赖时不套用并行：先派前置任务，产物就绪后才派依赖任务，禁止“先启动另一个 Agent 等着”。

## 6. 集中验收与修复

收齐最终报告后一次检查允许范围、真实差异、测试证据、未解决项和必要的视觉/性能结果。不默认重跑两套完整测试；具体疑点做定向复验。必要的广泛回归由风险/改动要求决定，不能为了省调用省掉必需验收。
问题集中退回原执行者，给出文件、复现输入/命令、预期/实际、证据和边界；继续由其自行修复后一次终报，不零散多次喊回。达到修复上限仍失败时，仅默认模式可考虑 Cursor，不能无限反复。
功能验收通过后才可整合；整合本身的授权和主分支/部署批准仍单独遵守。完成报告说明实际参与者、文件、测试与修复、未解决问题和“留在 Worktree/已整合”的真实状态。

## 7. 视觉与性能验证

- 根 AGENTS 十条视觉准则保持有效。美术/UI/动画以真实游戏 Camera 输出及明确动态覆盖为准；Headless、外部静止视口或仅参数检查不能替代。
- 复用 `tools/run_regression_suite.ps1` 的 Headless/GPU 分类和现有测试；按任务选择 Names、独立输出和用户数据。GPU 测试串行，后台隐藏/最小化、静音，不占用户主屏。
- 检查当前 Godot 可执行文件和工程解析；退出码、断言失败、脚本错误、证书/Wacom/dummy renderer/退出资源诊断分开，不宣称“全日志干净”。本次恢复任务不运行这些测试。
- 性能注明硬件、入口、Camera、分辨率、负载、预热和样本；不能把冻结场景、CPU draw_span 或中位数当作稳定 FPS / GPU 时长 / 因果结论。读最新 PERFORMANCE_RECORDING 与相关报告，不叠加嵌套耗时，不藏掉预热和死亡停留。

## 8. 指定 Agent 模式与额度限制

识别“本次使用 Codex/Antigravity/CodeBuddy/Cursor 执行”及同义“只让某个 Agent 做”。优先级固定为：用户指定 > 默认调度 > 并行优化 > 额度优化 > 自动故障切换。
当前任务及子任务、编程、非 AI 工具测试、自审和返工只能由指定 Agent 完成。禁止其他 AI 开发/交叉审核/协助、自动换人或自动模型降级；Codex 对指定其他 Agent 只做必要路由与状态传递。指定者不可用时报告用户并停止该路径，不能用 Cursor 悄悄接管。任务结束后才恢复默认按需调度。

本次 `team capabilities` / `config capabilities` 没有 task-scoped Agent/model 锁、allowlist 或锁令牌接口；team_task_update、team_send_message 对成员开放，owner 与提示词不是技术权限边界。不能声称底层强锁已实现。
需要严格指定时，明确该限制并采用对应 Agent 的独立非团队会话，关闭团队、子代理、其他 AI 接口并固定可用模型；需要不可绕过保证则另需服务端工具/模型白名单、网络/进程隔离或执行网关。当前没有安装这些锁基础设施，也未验证所有独立会话的后端绝不降级。
默认模式遇到额度/工具问题可有依据地接管；online 只表示注册/最近连接情况，不保证下一次模型请求额度。报告真实错误，不改凭证或杜撰执行结果。

历史并行验证位于本机 `E:\GameProjects\AIWorkspaces\parallel_dev_test_20261026\reports\`：16/17 项执行者测试、一次返工、Codex 3轮、执行期额外唤醒0。那是特定任务的历史结果，不是所有未来任务保证；不要重跑完整任务来验证历史。
调用统计按实际 lead turn_start、区分规划/执行额外唤醒/集中验收，重复启动或系统 idle 触发也如实计入相应窗口。它不是提供方 API 请求或 Token 账单，没有对照不声称节省百分比。
