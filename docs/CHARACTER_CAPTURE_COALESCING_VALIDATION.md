# 角色完整同步合并试验（2026-10-06）

## 当前状态与边界

**最终结论（2026-10-07）：否决接入，候选已撤回。** 较贴近正常频率的同画面对照证明它更慢，下面保留完整调查过程及失败结果。实验分支、专用测试及其生成 UID 已移除；既有枪口快照优化、弹壳图集和其他已验证优化保持不变。旧 `--frame-sync-ab` 参数明确退出 2，避免静默运行错误对照。历史候选当前不能直接重跑，需从会话补丁恢复实验代码；日志和文档未删除。

历史候选曾仅由 `test_frame_coalesced_capture` 开关启用，正式游戏默认不启用。它合并被动显示复制、材质与阴影更新，不减少人物玩法更新或瞄准迭代。正式位置、朝向、握持参考面和枪口快照仍同步计算；旋转、死亡、隐藏等特殊姿态及显式 `_process(0)` 保留立即完整同步。

## 否决过的调度方式

初版用 `RenderingServer.frame_pre_draw` 合并，同帧两次普通同步和快照请求可合为一次。最初 592 项通过，但扩展换枪后发现画面首帧差异；测试初次新增断言也误把合法原点当作“房间不存在”，修正并保留失败日志。进一步固定每组初始位置、姿态和正式指针，旧重复稳定而新路径的九组直立首帧仍不同；675 项的扩展第一次失败 16 项，第二次失败 11 项。差异图片 `.runtime/furniture_face_review/frame_sync_pose0_1.png` 与 `_2.png` 记录了 268 个不同像素。

补上同步几何后，坐标差异消失，但首帧图像仍有九项差异。推迟被动复制到渲染前信号不符合首帧契约，**否决此时机**。它的实际交火对照虽负载合格（敌方 294/328/321 发，原→候选→原 P95 25.103→22.786→28.314ms、退出 0），因视觉验收失败，不能作为当前可交付优化收益。日志 `.runtime/character_frame_sync_combat_ab.log`。
