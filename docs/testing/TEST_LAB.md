# 独立白盒与功能／性能测试场

入口：`scenes/testing/GameTestLab.tscn`。正式 `scenes/app/main.tscn` 不变。

## 启动与操作

- 双击工程根目录的 `Run_Test_Lab.cmd`。启动器使用 `.runtime/test_lab/appdata` 隔离用户数据，不写正式游戏进度。
- 其他电脑没有自动找到 Godot 时：`powershell -File tools/run_test_lab.ps1 -Godot "C:\你的路径\Godot.exe"`。用当前项目相同的 Godot 版本。
- 也可在编辑器打开上述场景按 F6；该场景关闭进度保存，但 F6 的设置／F3 记录目录沿用编辑器的用户环境。需要完全隔离时用启动器。
- **F1** 开关面板，**F8** 隐藏测试 UI 后截图，**F9** 开始／停止采样，**F10** 完整重建；Esc 显示面板。
- 面板开启时暂停玩家移动／鼠标攻击，防止点击控件时误开枪。F1 收起后使用正式 WASD、鼠标、空格、E 等操作。
- 面板可滚动。种子、敌人数、家具、AI、机器人／无人机配置需点“应用配置 / 重建整个场景”。房间下拉框用于传送到安全地板。武器选择为拳头、手枪、步枪、霰弹枪、球棍。
- 免伤只在测试玩家上生效，不改变正式生命值、伤害或受伤逻辑；关闭后可以测试受伤和死亡，F10 重置。

## 三种场景

| 模式 | 用途 | 注意 |
| --- | --- | --- |
| 白盒 | 固定四区：移动、射击／掩体、烟雾／门窗破坏、密集交战。32 游戏像素一格 | 中性材料、无城市布景、无地面反射；成绩不能代表正式视觉成本 |
| 同布局正式美术 | 同一四区几何、正式纹理／灯光／后处理／家具／特效 | 对照白盒，检查真实渲染与截图 |
| 正式随机楼层 | 使用正式骨架生成器、正式美术与渲染，按种子生成 | 敌人数量和 AI 由测试台控制，不是完整战役或跨层验收 |

门窗、物理家具、敌人、角色、射击、烟雾、燃烧和破坏均调用项目现有实现。测试世界只控制布局、生成数量、免伤和排除项；没有复制第二套战斗逻辑。

关闭“场内家具”会跳过主体家具生成，并在准备阶段移除美术布景额外添加的盆栽及其展示载体。**采样阶段场内确实没有家具**，但这不是“零家具生成时间”测试。关闭 AI 会暂停敌人及武器子节点，保留其呈现；敌人数 0 则不生成普通敌人。特殊单位单独开关，可能额外增加节点数，实际数会写入配置。

投影开关只控制室内灯投影，保留灯光；地面反射、Cutout、像素化、调色板、色调增强均可单独切换。白盒替换材料后不用于评价 Cutout／材质 shader 成本，应在正式美术模式对比。

## 负载与记录

1. 选场景、种子、房间、武器和排除项，重建；不要在同一轮里连续改变多个变量。
2. 选择手动记录、固定姿势基线、自动开火、开火＋烟雾／灭火器，或混合事件压力。
3. 按 F9。基础场景等待至少 2 秒且 90 帧后开始采样，自动事件在采样中发生。这个等待**不预演烟雾等首次特效**，首次触发峰值会保留。
4. 自动开火通过正式武器攻击入口，包含真实弹药与换弹。混合事件依次触发破坏、血液、灭火器、燃烧、烟雾；需要对应对象存在。报告记录触发成功／失败，不能把找不到目标的一轮当作有效压力测试。
5. 到时、F9 手动停止、重置或正常关闭窗口会导出本轮结果。进程被强杀／崩溃不保证尾部采样保存。

输出在隔离用户目录的 `test_lab` 下；面板可“打开输出文件夹”。每次输出独立目录，不覆盖前一轮。

- `frames.csv`：逐帧墙钟间隔、前次绘制提交墙钟、物理回调步数、延迟视口计时、Cutout CPU 计时、存活状态／房间。
- `report.json`：配置、P50/P95/P99/最大值、16.667/20 ms 超标数、触发和开火事件。存活帧与全部采样分别统计。
- `RESULT.txt`：便于快速阅读的摘要。
- 截图目录：实际游戏相机 `camera.png` + 当时的 `config.json`。F8 不在采样中执行，防止 GPU 读回／写盘污染时间。

F3/F4 的现有诊断系统保留，常规场景启动会另存其详细实玩记录；本测试台的报告是独立的受控窗口。应比较相同启动方式，避免将开启详细探针的成绩与无探针对照混用。

### 测量边界

- 帧耗时由相邻主循环时钟计算，不靠平均 FPS 猜测，采样窗口内不删除慢帧。缓冲上限 72000 帧／4096 事件，达到帧上限会结束并标记。
- `pre_draw → post_draw` 是 CPU 侧墙钟区间，**不是纯 GPU 执行时间**；视口 CPU/GPU 查询有延迟，不能直接指认为同一行玩法事件的耗时。
- 固定种子与动作时序让配置可复现，但真实物理、操作、运行调度及部分特效随机数不是逐像素确定性回放。
- 重置并不清空驱动 shader cache。首次启动／首次事件与同进程热复用需分别测；不要删除用户显卡缓存。加载、重建、截图、导出不属于此工具的游玩采样区间。
- 白盒和短测不能证明全游戏稳定 60 FPS；正式入口、电梯、跨层和真实战斗仍需最终回归。

## 新内容的正式接入门槛（2026-11-02 用户确认）

1. **先隔离接入测试场**，验证输入、碰撞、受击、首次使用、重复使用、重置与退出，无异常和残留。
2. **保留新内容之前的基线**，在同种子、房间、敌人数量、AI、分辨率、限帧和画质设置下做 A/B/A 或重复配对。不要通过删地图／家具／敌人让结果好看。
3. **测真实呈现与组合负载**：渲染新功能必须在正式美术模式用实际相机检查；同时测试交战＋新特效叠加，保留首次触发峰值。
4. **确认有足够流畅性后才加入正式游戏**。如新内容造成明显卡顿或峰值退化，留在测试场优化，或让用户决定取舍，不能直接推广。报告要包含 P95/P99/峰值与超标帧，而不是只给平均 FPS；未达到既定目标时如实报告，不把 20–30 ms 称作稳定 60 FPS。
5. 正式接入后再走真实游戏入口回归。测试场通过不豁免主场景／跨层验证。

## 维护与自动验证

- 布局：`scripts/testing/lab_layout.gd`；测试世界：`lab_world.gd`；面板／负载：`game_test_lab.gd`；记录器：`lab_recorder.gd`。
- 新增项目优先扩展独立触发和可控负载，不向正式入口添加测试菜单或默认开关。
- 自动检查：`tests/game_test_lab_test.gd`，使用隔离 APPDATA。无窗口运行验证逻辑；有窗口离屏运行验证实际 Camera 截图与导出。无窗口成绩不作为渲染性能成绩。
- 正式源文件仅为测试世界开放原有地板寻路缓存的白名单，避免继承测试脚本意外退回慢路径；正式世界的行为和缓存条件不变。
