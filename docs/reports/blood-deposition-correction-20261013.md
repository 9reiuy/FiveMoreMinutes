# 修正血泊的中心扩圈表现

> 本文记录已被下一版替代：见[空中泼洒与尸体擦痕修正](blood-flight-smear-correction-20261014.md)。当前死亡池仅保留局部伤口沉积，远处血斑由真实飞行血滴触地生成，旧110滴地面预置参数已移除。本文旧录像的 `rifle` 伤害标签没有触发正式枪击喷血，只能证明死亡池，不能证明枪击空中泼洒；新录像已使用真实子弹碰撞验证。

用户指出上一版仍像蒙版放大。核查确认：上一版虽然没有放大像素，但按距中心的半径排序，再按面积比例逐圈显示。只改变最终轮廓无法解决这个动态问题。该版效果已被用户否定，先前自动化通过不能视为视觉验收通过。

## 当前实现

正式死亡血泊改为独立血斑沉积，不使用径向排序、全局半径揭示或透明度渐入。每块血斑以最终位置、最终尺寸和完整不透明度出现，已经落下的像素不移动。主体由大小不同、方向不同的碎边血斑重叠组成，保留中等血斑、细长喷射指状痕迹及外围独立小滴之间的空隙，缩小此前过大的均匀核心。

死亡池沿实际死亡受力方向布置主要散落扇区。原死亡位置、落地触发、伤害、尸体运动、出血源和死亡寿命保持现有规则；此修正改变血液表现。橙色、最近邻、1px、原地面/墙门裁剪、8192格预算、落定合并冻结和换层回滚继续沿用。

初始散落已经包含远处溅点。主要沉积发生在落地后的约132ms，最后少量伤口附近的沉积持续到550ms；该时间窗不代表向外扩张动画。捕获仍最多30Hz，首次可见时直接显示已沉积血迹。对16个固定种子验证，140ms时已显示至少90%的最终像素，现存像素位置和透明度不变。

## 参数

| 位置 | 参数及默认值 | 用途 |
|---|---|---|
| `scripts/dream/dream_3d_random_dungeon.gd` | `OFFICE_BLOOD_POOL_GROWTH_SECONDS=0.55` | 沉积窗口，秒；原1.2 |
| `scripts/entities/black_blood_effect.gd` | `POOL_DEPOSIT_BURST_FRACTION=0.24` | 0–1，主要喷溅占窗口的前24% |
| 同上 | `POOL_DEPOSIT_SPLATTERS=110` | 外围小滴/小块数量；增加会提高密度和生成成本 |
| 同上 | `POOL_DEPOSIT_MEDIUM_PATCHES=12` | 中等独立血斑数量；增加会填满更多空隙 |
| 同上 | `POOL_DEPOSIT_EDGE_SAMPLES=64` | 每块不规则边缘采样数量 |
| 同上 | `_setup_deposited_pool()` 中四块主体规格 | 中心、半径与到达时间；尺寸不在运行中缩放 |

`OFFICE_BLOOD_POOL_START_SCALE=1.05` 只用于旧形态比较的接口兼容，正式沉积不使用起始比例来揭示像素；`END_SCALE=2.05` 用于选取一次性的最终形态大小。原 `POOL_SATELLITE_CLUSTERS` 等角向轮廓参数只供明确选择旧径向路线的比较夹具。

## 动态 Camera 证据

实际 Main、自然配置的敌人、真实伤害进入死亡、正常敌人/血液/跟随源更新，使用真实RTX5070Ti、1920×1080游戏Camera。为避开PNG读取引起的时间步长跳跃，动态录像固定游戏时间步长1/60；这不作为60FPS性能测量。其他敌人停用、玩家无敌和定位只用于可重复视觉夹具。

原生窗口最小化。新版连续输出103帧，覆盖约2.617秒游戏时间；6项链路检查零失败。没有人工推进死亡函数、血泊函数或尸体根位移。原始PNG和时间记录在 `.runtime/blood_deposition_revision_20261013/camera_fixed/`。

## 验证与仍未验收项

形态测试452项检查零失败，涵盖16个种子、首帧分散、远处溅点先出现、早期形成主体、像素不移位/放大/渐入、生成预算、随机流和裁剪。

16项相关Headless脚本全通过，记录1274项检查；未输出计数的脚本保持空值。包括墙门/薄障碍查询、跨房间、血迹合并、跨层恢复、尸体跟随、拖痕、接触及寿命。日志在 `.runtime/blood_deposition_revision_20261013/regression/`。

三项真实GPU回归零失败：捕获重绘35项、裁剪Camera一致性30项、合并Camera18项。新版与旧路线的两个死亡录像各6项检查零失败。退出仍有既有纹理/音频资源清理告警，原日志保留。

本次离树形态生成16次测试，新路线中位8.171ms、P95 8.938ms；旧径向原始路线中位7.832ms、P95 9.699ms。无真实碰撞/渲染，不能推出整场帧率改善。上一轮600秒正式流程及全工程回归结果是旧形态版本的证据，本次未重跑全部清单或600秒性能验收；稳定60FPS、加载等待和中档实机仍未验收通过。

动态画面已核对；与用户参考效果的最终主观匹配仍由用户验收。
