# 1-1 机库人员与返回布景

首次进入机库时放置两名科学家和一名工程师，使用已有 Scientist、Scientist2、Engineer 原画与独立安全帽，围绕用户标图的机甲左下、右上、右下三个工作位置活动。左侧科学家检查关节、短距离走动后记录；右上科学家记录读数并换位置观察；工程师走近关节蹲下检修，起身查看工具后返回。三人的循环时长不同，沿用原有睁眼／半闭眼／闭眼帧并错开眨眼，转向时保留背身身体与腿、帽子的三像素对齐修正。

三人为非战斗剧情人员，禁用攻击、感知、受伤及战斗碰撞，不登记敌人、不计入清敌、不提供击杀奖励或掉落。活动由独立呈现控制器驱动，敌人 AI／物理回调继续禁用；正常暂停会停下活动，区域隐藏或卸载也会停下并释放。复用正式角色光照与姿态渲染。

1-2 出口启用返回机库区域时，尸体散落到西侧、北侧与南侧出口附近，每人相对原工作点移动超过三米，尸体之间超过八米。三条拖痕分别约 5.42、5.94、7.42 米，末端增加交叠血泊。预加载时不提前显示血迹，重复激活不叠加；返回存档重试恢复尸体，从头开始恢复活人。

长拖痕使用原有 BlackBloodEffect、pixel_blood_drag 与原遮罩合并结果，没有重画或改变血色。七份原遮罩保存为约 10 KiB 的原生纹理资源，按原位置及 0.045 米高度显示；正常返回只显现静态布景，不创建血液模拟和捕获视口。修正了合并过早冻结在旧 0.02 米高度、导致格栅遮住拖痕的问题。保留原绘制入口供烘焙与对照使用。

## 修改位置

- `hangar_crew_actor.gd` / `hangar_crew_activity.gd`：非战斗角色、工作活动与原有眨眼动画。
- `hangar_crew.gd`：活动生命周期、分散尸体与拖痕布局。
- `hangar_crew_blood.gd` / `hangar_crew_blood_data.gd`、`art/Dream/SceneDressing/HangarCrew/`：原血迹遮罩的静态呈现、生成来源及位置数据。
- `chapter_world.gd`：新增修订默认开启。以上脚本均位于 `scripts/testing/h06_chapter/`。
- `chapter_art.gd`：门禁判断补充显式 bool 类型，未改变判断逻辑；保留共享工作树同时进行的门禁与布局更新。正式角色渲染器沿用上一轮已接入的剧情角色姿态元数据。

## 本机验证

Godot 4.7.1、Forward+ / Vulkan、RTX 5070 Ti、1280×720 实际 Camera；启动前私有音量配置为零，保留 WASAPI 驱动，未改变玩家音量。

- 独立关卡检查 **101 项通过**，包含三人确实走动、不同工作动作、各自可见的闭眼帧、眨眼错开、工作路线不穿越机甲高台、正常暂停恢复，以及之前的对齐、无法伤害、预加载、卸载、重试和新游戏恢复。
- 现有第一章入口检查 **48 项通过**，默认启用工作活动，经实际 1-2 出口切换到分散尸体与血迹，返回存档及新游戏恢复正确。上述最终日志无 ERROR / WARNING，进程正常退出。
- 实际 Camera 中静态版与原绘制版的 **8694 个血色相关像素逐像素完全一致**。这项对照只声明血迹画面，不声明整帧其他对象完全一致。
- 已检查实际 Camera 工作姿势、返回布景和长拖痕；另保存 90 帧实际相机工作动画，截图与录制不参与性能采样。
