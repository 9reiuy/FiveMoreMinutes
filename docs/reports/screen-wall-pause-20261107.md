# ESC 显像管暂停界面

正式 `scenes/ui/pause_menu.tscn` 已采用单台电视界面，沿用原暂停控制器和 PauseManager 的继续、设置、返回主菜单与暂停原因管理。原试玩入口 `tools/preview_screen_wall.cmd` 仍启动正式游戏。

![设置与斜纹滑条](../../.runtime/screen_wall_pause_20261107/pause_settings.png)

## 最终画面与操作

- 打开暂停时，真实 3D 电视从屏幕上方快速落下，0.21 秒到达略低的位置，再用 0.075 秒向上回拉、0.055 秒收稳，总长约 0.34 秒。关闭会取消未完成的动画。
- 暂停和设置的全部文字、按钮、滑条、复选框及返回按钮都在 480×360 控件视口内，再映射到弯曲玻璃。交互会反算显像管畸变，保持鼠标与控件位置一致。
- 电视外背景为黑色，电视内包含弯曲扫描线、细噪点和辉光。界面统一采用滑条的 `#82ABBA` 灰蓝色相，以亮度区分状态；选中条内文字为背景黑色。此连续荧光色处理只作用于暂停电视，没有接回全局调色板量化。
- 三个音量滑条采用参考中的细矩形外框、斜线填充和末端 I 形游标。原生 HSlider 继续处理拖动、步长和数值，原有设置保存与音量逻辑保留。
- **只有进入设置**使用约 0.17 秒的从上到下扫描切换；返回暂停仍沿用原淡入，继续和返回主菜单不附加扫描。
- 扫描使用两个可复用 GPU 控件缓冲。冻结旧页后将同一组实时控件移至另一个视口，以扫描线逐步揭示新页，不在点击时读取截图。
- 原悬停短音、UI 音量通路和 -9 dB 衰减保留，单声部替换播放。关闭暂停会停用三个渲染目标及其处理，取消动画与悬停音。
- 修复了现有设置辅助页仍用旧 `Rows/...` 路径的问题：Rows 在初始化时已移入 RowsCenter，现在通过缓存节点访问各行，辅助复选框可以正常使用。

## 接入与范围

新增实现为 `screen_wall_pause_menu.gd`、`screen_wall_pause_view.gd`、局部 CRT/辉光着色器、斜纹滑条与选项绘制器。原 `pause_menu.gd` 仅将按钮容器类型放宽至 Control，行为接口保留。共享电视墙仅抽出模型和显示器创建方法，主菜单仍使用原默认模型、角色和灯光。

先在 GameTestLab presentation 中将候选暂停节点接入真实 Main 和 3D 游戏，完成操作与实际 Camera 检查，再替换正式暂停场景。候选包装场景随后直接继承正式场景。旧暂停场景保存在测试夹具中作性能对照。

素材、生成方法及 CC0 来源见 [资产说明](../../art/preview/screen_wall/pause/ASSET_SOURCES.md)。改动留在当前共享工作树，未提交；其他任务的已有改动保留。

## 开始准备与菜单性能

初次测量发现第一个 ESC 帧有 273.775 ms 的准备停顿，原记录保存在 `perf_before_warmup.json`。现在在启动时于不可见视口提前准备电视、字体和页面缓冲，再停用它们。该轮启动准备墙钟为 647 ms，包含当时的加载和绘制等待，不能单独视为纯 GPU 时间。

修正后首次 ESC 调用 CPU 为 0.737 ms，随后的前 8 个帧间隔为 13.398–16.678 ms。准备成本移到了启动阶段，没有声称总启动时间被消除，也没有删除缓存、减少游戏美术或灯光来得到结果。

相同暂停世界、相机、分辨率 1280×720、VSync 与私有音频设置；每例预热 1 秒后测量 4 秒。原生窗口位于屏幕外，没有强制绘制辅助或截图采集。
