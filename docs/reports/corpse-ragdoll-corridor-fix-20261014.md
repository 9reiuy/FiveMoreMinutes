# 死亡布娃娃击退与空中走廊玻璃修复

用户确认沿用现有攻击受力配置、伤害和尸体寿命；走廊通路与两端连接口禁止阻路玻璃，平行侧边围护保留。本轮自行执行，无子智能体，所有实际GPU录像和运行检查保持窗口最小化。继续以实际Camera动图交付。

## 死亡受力

原实现已包含肢体弹簧布娃娃与尸体运动，但致死受力只转换45%为水平速度，空中与地面统一以380px/s²减速；枪击因此很快停止，位移较小。主体运动还在渲染更新中推进。原枪击来源共用300受力值，未按枪种独立设定；按本次共识继续保留这一配置。

现在整具尸体由固定物理步推进，继承已有运动惯性并承受致死受力；渲染更新只处理肢体表现、明度和寿命。空中阻力与地面摩擦分开。使用原7px主体足印扫掠实际墙、门和家具，在碰撞接触法线处保留部分切向滑动并轻微反弹；真实地板边界继续阻止尸体进入虚空。静止后主体停物理更新，既有尸体接触传感器仍可唤醒运动。死亡源位置缓存、一次死亡结算、掉落、出血及15秒寿命规则继续沿用。

方案沿用当前精灵肢体弹簧模型，主体使用实际Node2D物理空间的扫掠碰撞与惯性积分。肢体姿态由原布娃娃求解器处理。普通枪击并没有新增武器伤害或独立枪种倍率。

全部新参数集中在 `scripts/data/demo_config.gd` 的 Corpse Presentation 组；现有 `resources/demo_config.tres` 使用这些默认值。名称、范围与影响如下。

| 参数 | 默认 / 编辑范围 | 影响 |
|---|---|---|
| `corpse_impulse_transfer` | 0.75 / 0.1–1.5 | 致死受力到初始水平速度的换算 |
| `corpse_inherited_velocity_ratio` | 0.35 / 0–1 | 保留死亡前移动与击退惯性的比例 |
| `corpse_max_launch_speed` | 360px/s / 60–600 | 尸体初始水平速度上限 |
| `corpse_air_drag` | 40px/s² / 0–300 | 空中水平减速 |
| `corpse_ground_drag` | 320px/s² / 50–800 | 落地后的滑动减速 |
| `corpse_wall_restitution` | 0.18 / 0–0.5 | 撞击法线方向反弹比例 |
| `corpse_wall_slide_retention` | 0.65 / 0–1 | 撞击后切向滑动保留比例 |

空旷场景的七种伤害来源检查：三类枪击沿用300受力，初速225px/s、主体最终移动约122.82px；踢击沿用600受力，受速度上限约束，移动约343.71px；Lucille与Books分别沿用1200/900受力，约363.59px；家具冲击180受力，约50.67px。实际距离会受到墙、家具、已有惯性和地板形状影响，不能保证每次击杀都有相同位移。

## 走廊根因

在V3骨架、种子120/42001/42002中复现：`crosshall` 横向空中走廊与 `main` 办公区的一个端面没有被拓扑列为必需通路。后续办公室玻璃立面遍历这条共享边，在4格宽的走廊端面中间生成2格玻璃，两侧各留下1格墙。整个入口被封闭，虽然房间图仍可经另一端连通，原全图连通检查不会发现这一局部问题。

`office_skeleton_layout_adapter.gd` 集中判定横穿走廊端面的边：方向垂直于走廊长轴、位于其端线、且实际跨度相交；避免把平行的侧面玻璃误删。原生生成器在玻璃插入阶段将无入口的此类端面改成整条实际共享接触边的开放入口，因此新入口也进入家具避让与通路规划。已有正常入口时不再填入端面玻璃。编译器同时处理旧来源，只有全宽两侧确属同一对房间时才扩大开放范围，防止跨到虚空或第三个房间。删除玻璃时同步生成OPEN连接，避免留下替代墙或不可见碰撞。

新V3复现入口开放4格，侧边玻璃继续存在。A1/B2/C3本轮固定快照未变化；其他走廊同样应用端面通路规则。

## 回归及快照更新依据

新死亡受力专项40项通过：七种来源、惯性继承、反方向、落地摩擦、真实墙约束、渲染不能重复移动尸体、死亡源缓存与寿命。墙边专项暴露了休眠速度阈值以下仍残留极小速度，已在休眠时清零并重跑通过。

走廊规则专项53项通过，覆盖4种骨架与3个种子、侧玻璃保留、旧来源编译为开放通路。原生骨架40种子运行检查286项通过；其他尸体接触、拖痕、跟随、表现与布娃娃脚本通过。生成器查询/编译一致性1546项通过，候选净空缓存600项通过；净空生成一致性12个场景通过。正式四种骨架GPU运行检查264项通过，涵盖正常输入、家具/敌人预算、独立玻璃、边界状态、玻璃破坏等。

旧快照以“地图完全不变”验证生成优化，与本轮明确开放V3入口的规则冲突。保留原快照后，仅更新V3的4个源码哈希与3个净空场景签名；逐项验证A1/B2/C3和调用方随机状态不变。变更前后值及原因保存在 `generator_baseline_changes.json` 与 `clear_baseline_changes.json`，旧值保存在同目录 `before/`。没有仅为通过测试恢复阻路玻璃，也没有删除旧失败证据。

初次整体回归包含受力专项失败，后续修复后专项通过；初次生成一致性清单有3个旧V3签名失败，更新经确认规则的快照后重跑通过。相关总表应分阶段阅读，不能把初次失败表称作全通过。未输出断言数量的脚本未补算。

GPU退出仍有既有两份纹理清理告警。本轮没有重跑600秒完整性能验收，整场帧率、换层等待和中档实机状态未变化。

手动复查：用不同攻击从不同方向击杀敌人，观察尸体受力、落地、滑动与墙/家具碰撞；静止后推踢应重新运动。V3横向空中走廊应能从两端正常进入，側邊玻璃保留；换层后新生成走廊也不应再次封闭。
