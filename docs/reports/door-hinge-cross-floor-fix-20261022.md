# 跨层后门板绕中心旋转修复

日期：2026-10-22

## 原因与修改

真实跨层流程会在新楼层生成后暂停门体，等待轿厢加载。CollisionObject3D 默认在处理被禁用时从物理服务器移除；门轴两端因此被注销，恢复后门板失去铰链约束，绕自身中心旋转。

仅将 PhysicalDoor3D 的门轴锚点及门板设为 DISABLE_MODE_KEEP_ACTIVE。加载期间仍沿用原有冻结、清空碰撞掩码、隐藏和暂停更新逻辑；没有改变门框位置、模型、推门力度、伤害或其他战斗参数。

## 验证结果

- 门轴边缘专项：96 项检查，0 失败。覆盖单扇/双扇、横纵朝向、45°楼层旋转、碰撞同步、暂停恢复、敌人推动及真实分阶段跨层。
- 原门轴与裁切回归：19 项检查，0 失败。
- 跨层生命周期回归：729 项检查，0 失败。
- 同一跨层复现中，26 个门板修复前最大门轴边缘漂移约 0.75656 世界单位，修复后约 0.000422。
- 正式入口及 Camera3D 的 GPU 对照：RTX 5070 Ti；真实跨层后正常推门，旧策略漂移 0.663360，修复后 0.000411。

GPU 对照位于 `.runtime/door_hinge_20261022/before/` 和 `after/`，包含关闭状态及五个开门时刻。最终 `swing_47.png` 已人工查看。旧策略只在测试实例中恢复，未回写生产代码。该画面测试使用无敌人生成的楼层夹具，不等于完整自然游玩或性能测试。

## 单独记录的已有问题

敌人门口寻路回归 23 项中有 2 项失败：生成门的敌人跨越、调查状态的正式门路线。恢复旧门体策略重跑仍为相同 2 项失败；不作为本轮新增失败，也未扩大范围修改 AI。

部分测试退出仍有 ObjectDB/资源或渲染资源释放警告，不宣称日志零警告。工程中另一个正在改动的 `_DroneGameDiag` 自动加载会干扰独立测试；仅在本轮自有测试进程内移除了该节点，未修改其脚本或 project.godot，也未停止用户编辑器与游戏。
