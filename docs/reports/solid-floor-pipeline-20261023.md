# 实心地面不透明渲染通道修正

## 结果与边界

正式随机楼层、样板地面、局部地毯、接待区装饰地毯、备用地板和独立电梯地面现在使用独立的不透明地面材质。没有把玻璃、烟雾、家具挖洞或门墙渐隐一起改成不透明；没有关闭深度测试、强制特效置顶或修改战斗数值。

这次解决的是“实心地板错误进入透明队列，在部分地格批次后绘并覆盖不写深度的特效”这一根因。真正半透明物体互相交叠的排序限制仍是另一类问题，不宣称一并消除。

## 实现

- 新增 `office_floor_opaque.gdshader`，从已批准的地板着色数学中分出独立地面版本，不再读写透明输出，不包含家具的透明挖洞代码。
- 新增 `office_floor_swatch_opaque.gdshader`，用于地面专属色板及需要显式指定为地面的布料/木纹/瓷砖。家具继续使用原有着色器。
- 保留原有纹理资源、UV/像素采样、法线倒角、粗糙度、漫反射、抖动光照和反射包裹方式，不用“ALPHA=1”冒充不透明通道。
- `make_floor` 使布料等共享纹理可以分别拥有地面与家具材质，避免误改同一纹理的家具用途。
- 抖动光照明确支持两种新地面着色器；反射系统将原始地面色板视作共享缓存，使用拥有者局部变体，防止换层/回滚污染共享材质。
- 原有冲刺、残影、挥击的可见像素深度策略保留。现在即使测试特效故意不写深度，也不会再被实心地板的透明后绘阶段覆盖。

## 视觉验收

RTX 5070 Ti / Compatibility 实际 GPU：11 类地板、33 个纹理变体、11 个反射版本，以及8种备用地面色板，共 **52组前后对照**。每组比较同相机、同光照、相同纹理资源的128×96像素采样区，最终最大和平均RGB通道差均为 **0/255**。

旧材质对照来自原始家具着色器及原有抖动/法线/反射构建流程，不是改变贴图颜色来伪造对照。

实际 Main → 正式楼层相机中，检查了85个活跃地面表面，反射包裹后的地板和局部地毯均没有透明输出，原有反射纹理仍绑定。查看了同楼层的实际相机前后画面。完整画面 SSIM 约0.994917，不能称整帧逐像素相同：画面包含仍在变化的环境粒子，以及这次有意纠正的特效可见性。地面本身的定量像素一致性以独立受控52组采样为准。
