# 地板可读性与角色真实受光恢复

后续修正：本文的地面专用均匀补光已移除，当前照明与红海推广以 [真实灯具照明修正](coast-promotion-and-real-fixture-lighting-20261030.md) 为准。人物阴影接收修复继续保留。

2026-10-30。Codex 在正式工作树独立执行，未委派、未提交。本文取代前一份报告中将全场环境光降至 0.015 的处理。

## 地板与家具分开受光

用户反馈成立：此前降低全场环境光会连地板一起压黑，不能用“暗部更黑”作为验收标准。现在恢复正式楼层 0.17、教程 0.18 的环境光，原全场无阴影 KeyLight 继续为零。

`office_dither_lighting.gd` 对正式关卡及教程的家具主体使用场景内独立材质副本，关闭这部分材质的全局环境光响应；局部灯、手电及枪火仍真实照射家具。地板不使用这份家具副本，墙面也不会因家具分类被一起修改。教程武器台的标准材质同样处理。屏幕与指示灯的合理自发光保留。

地板使用单独的冷色 DirectionalLight3D 补光，接收层为 `1 << 16`，普通家具和人物不在此层。它是实际 3D 受光，不修改贴图颜色或增加地板 Emission。教程地板在调色后的亮度阈值更低，因此使用 1.0 能量；正式楼层原画地板使用 0.12。主灯与局部灯仍负责主要明暗、方向与阴影。反射系统不会把这盏地板补光扩展到人物／家具倒影上。

实机检查：教程 18/27 个采样点、正式楼层 14/28 个采样点相较先前过黑状态恢复可读亮度；9 个教程家具采样与 27 个正式家具采样在恢复地面环境照明时保持暗部，实际局部灯照射下分别有 1 与 16 个采样显著变亮。329 项包含逐件灯光层隔离检查，全部通过；这些数值不是性能结果。

## 玩家与敌人的真实受光

根因是 `dream_3d_actor_depth_bridge.gd` 在启用体积投影模型时，为可见人物动态生成 `shadows_disabled` 材质，直接禁用了其阴影接收；默认 0.10 的材质自身补亮又冲淡了环境照明。

修复后玩家与敌人使用原本可以接收真实阴影的 `lit_pixel_carrier.gdshader`，自身补亮降至 0.01。保留现有身体投影模型、手持武器、2D 玩法和角色原画。眨眼、受击闪白、手机蒙版光及轮廓用途不变。

## 实机验证

- `tests/actor_world_light_receiver_test.gd`：实际 Main 正式楼层、实际游戏 Camera，10 项通过。同一位置的真实玩家／员工，依次关闭验证灯、开启真实 OmniLight3D、加入仅投影的实体遮挡物，再移除实验物件并恢复关卡原灯。控制实验阶段暂时隐藏两人的自身体积投影以隔离环境遮挡，恢复原灯截图前重新恢复投影。
- 玩家局部区域亮度：0.178 → 0.452 → 0.177；敌人：0.081 → 0.256 → 0.081。ROI 包含邻近背景，用于相同画面的光照／遮挡变化验证，不能解释成人物表面精确照度。当前受控灯光实验不是新增正式摆放灯具。
- `tests/test_character_lighting_authenticity.gd` 通过。
- `tests/actor_volume_shadow_test.gd`：86 项通过，投影体、姿态、投影生命周期及玩法位置保持。
- `tests/floor_furniture_balance_test.gd`：329 项通过，实际 Main 教程与正式楼层，包含两套配色。
- 定向 `git diff --check` 通过。
