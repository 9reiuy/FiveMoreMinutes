# 塔罗大厅修正交付

本轮按用户批准的五项修正实施，保留现有大厅布局、唯一左工位 NPC、塔罗规则及电梯换层流程。

## 修正结果

- 地板复用正式楼层 `ApprovedOfficeArt` 最终接待区美术覆盖层：同一大理石纹理生成、法线、倒角材质及两格 UV 铺贴规则。共享地板重建入口，不额外生成楼层地毯和绿植。
- 后方三个工作台旋转 180°，员工侧朝向南侧座位。按真实 2.2×1.1 模型占地安排桌、椅、柜；碰撞同步该尺寸。实际模型 AABB 无重叠。
- 大厅继续隔离全局配色滤镜。实际 Main 画面下切换开关，地板区域像素相同、整个大厅包装器调色门控保持关闭；正式楼层仍恢复用户原有设置。
- 夜景环境光 .38、颜色 (.4,.44,.52)，主光 .025，均对齐实际正式楼层；降低原来的整体照明，采用局部顶灯与柜台、电梯照明，保留暗区。
- 大厅及正式楼层共用深色工业电梯外部门面。强化门板筋条、嵌入框、门槛、编号和状态面板。实际楼层南侧电梯会向固定摄像机露出门扇背面，因此门板两面均加入工业结构，并重新拍摄实际游戏视角。装饰附着原有运动门扇，保留原门洞、碰撞及开关动画；轿厢内部未改动。大厅仅 1 号可用，2/3 号关闭。

楼层补拍还定位到原井道黑色背板是双面薄盒，会从背面挡住关闭的门扇。已改为位于同一墙厚范围内的单面背板，保持走廊侧开门时的暗井道，同时让固定摄像机看到真实门板；门墙宽度、方向、凹入位置和碰撞回归通过。

主要文件：`dream_3d_reception_room.gd`、`tarot_reception_dressing.gd`、`preview/sample_floor_texture_review.gd`、`elevator_floor_door_3d.gd`、新增 `elevator_industrial_facade.gd`。

## 验证

相关九个逻辑脚本最新结果全部通过：大厅修正 35 条、布局 45 条、电梯音频 47 条、加载遮盖 21 条，以及门墙对齐、屏幕方向、独立电梯方向、接待交互和接待场景检查。断言数未由脚本报告的项目不计入总数。

门墙对齐旧断言要求“没有额外房间围墙”，与当前正式接待房间真实围墙不符。按现行房型区分正式接待围墙和裸门面，保留原门扇、门框位置与独立轿厢检查；纠正后通过。原失败日志保留在 `final_regression`，最新复测在 `corrected_regression`。

RTX 5070 Ti 实际 GPU 串行验收：

- 正式楼层四种骨架运行检查：264 条，0 失败。
- 正式美术纹理缓存与材质隔离检查：359 条，0 失败。
- 正式 Main 入口大厅交付检查：24 条，0 失败。普通移动输入经过闸机、休息区、NPC；正常对话与卡片选择信号完成抽牌，电梯 E 输入进入实际楼层；记录大厅及楼层门开关状态，并验证最终地板材质与滤镜隔离。

全部完成运行退出码为 0，无脚本错误。GPU 窗口在屏幕外启动后立即最小化，主智能体独立执行，无子智能体。

退出时仍有原有 GUI 锚点提示、两个纹理 RID 与少量资源释放诊断；本轮未将这些退出清理问题标记为解决。画面验收与功能断言通过不代表退出日志完全无警告。
