# 正式关卡调光与地面光圈：性能复核

2026-11-03。对应 [视觉整改](E:/GameProjects/FiveMinuteMore/docs/reports/formal-floor-lighting-readability-20261103.md) 的最终实现，不是另一项删减灯光／投影方案。正式游戏的四个调光文件保持原样；本次另修正了测试场在正式美术模式下漏装家具受光组件的问题。

## 结论

完成四轮实际交战对照，136 项负载与状态检查通过；固定同一份交战与烟雾画面的渲染隔离检查 9/9 通过。两版实际交战仍有超出 16.667 ms 的帧，不能宣称稳定 60 FPS。

固定画面合并 P50 为旧版 7.056 / 新版 7.279 ms，相差 0.223 ms。旧版自身 A1→A2 也出现波动，因此这项短测只支持“该镜头的增量较小”，不证明零成本或全局没有回退。实际交战的 AI、物理和残骸不是逐帧确定性回放，不能把所有差异都归因于调光。

## 修正测试场覆盖缺口

最初四轮使用测试场默认入口，随后隔离检查发现 `LabWorld` 的场景路径不在正式显示启动器的自动安装列表内：地面 shader 和调色已工作，但 `OfficeDitherLighting` 没有安装，旧版家具压暗与周期性材质刷新未被完整覆盖。

已修正 [测试场构建](E:/GameProjects/FiveMinuteMore/scripts/testing/game_test_lab.gd)：仅正式美术模式调用现有正式启动器安装组件，白盒模式不安装。两份运行副本使用相同修正；下列最终四轮逐阶段确认组件存在、正常刷新开启、旧／新版家具受光分支确实不同。安装逻辑幂等，探针重复确认不会添加第二份组件。

最初四轮数据保存在 [覆盖不完整的记录](E:/GameProjects/FiveMinuteMore/.runtime/lighting_perf_recheck_20261103/analysis_without_furniture_component.json)，不计入最终表。固定画面的两次准备失败记录也保留在 `frozen_invalid_node_lookup` 与 `frozen_invalid_missing_component`，分别是节点定位失败和组件缺失；均不计入有效成绩。这修正了早期进度说明中“正常材质刷新开启”的判断。

- 从同一工作树制作两个独立运行副本，初始核对 15,169 个文件，仅四个调光生产文件不同，无缺失；随后两份副本同步相同的测试场修正和探针。旧版来自本轮视觉整改前的实际文件副本，不以 Git HEAD 代替用户当前工程。
- Godot `4.7.1.stable.official.a13da4feb`，OpenGL Compatibility，RTX 5070 Ti，驱动 `617.42`。使用同一正式引擎，未使用诊断引擎。
- 测试场正式美术模式，种子 42001，4 个房间、13 组家具、8 个普通敌人、霰弹枪、灭火器与烟雾。阴影、反射、遮挡、像素化、调色方案 1、色调增强开启；未删减场景、敌人或战斗内容。
- 原生 GPU 后台最小化窗口，每帧绘制实际 Camera；外层 1280×720、世界 640×360，取消限帧／垂直同步。不是无窗口虚拟渲染器成绩。
- 香港时间 16:40:16–16:45:11，旧 A1 → 新 B1 → 新 B2 → 旧 A2。每个进程静止 10 秒、首次交战与烟雾 20 秒、同种子重建后重复交战与烟雾 20 秒。基础场景稳定至少 2 秒／90 帧；首次特效留在采样内。未清除驱动缓存，“首次”指本轮进程首次负载，不指清空缓存的冷启动。
- 与另一项相机测试错开；没有关闭用户编辑器或其他用户程序。完整墙钟原始帧保留，不删慢帧。视口 CPU／GPU 查询会延迟回传，不能用同一行事件直接归因某个尖峰。
