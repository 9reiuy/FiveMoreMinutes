# 深度策略与性能复核（2026-10-23）

## 结论与边界

本轮不修改正式游戏逻辑、材质或美术。新增诊断脚本 `tests/depth_policy_audit.gd`，只在自己的测试进程中临时切换地板 shader，测试结束恢复引用。

“检查深度”“写入深度”“计算自定义 DEPTH”“采样场景深度纹理”是四件不同的事。`depth_draw_never` 只禁止写入，仍检查遮挡；不能据此称为无深度。源码检索未发现 shaders 目录中使用 `hint_depth_texture` / `DEPTH_TEXTURE` 的效果；这不代表引擎没有深度缓冲或阴影图。

## 已核实的正式渲染路径

| 效果 | 深度策略 | 处理建议 |
| --- | --- | --- |
| 实心地板、地毯 | 不透明，检查并写入 | 保留；此前整格消失的修复主要是正确性，不是显著加速 |
| 冲刺残影 | 不透明镂空/抖动淡出，检查并写入；自定义参考平面 DEPTH | 保留，不能直接删自定义深度，否则改变遮挡 |
| 冲刺路径、近战挥光 | 不透明镂空，检查并写入 | 保留；切成半透明不会自动更快 |
| 命中月牙 | 不透明镂空，检查并写入；自定义 DEPTH | 保留 |
| 人物/武器 carrier | alpha scissor 与参考平面 DEPTH | 保留；有 ALPHA 不足以单独判断实际 pass，scissor 也参与路径选择 |
| 子弹/部分枪口 capture | 声明 alpha depth prepass，带 scissor、自定义 DEPTH | 需专项多弹测试才可删改，不能从声明推断一定执行两次完整颜色绘制 |
| 空中血滴 | MultiMesh；ALPHA 恒为 1，声明 alpha depth prepass | 优先候选：试验纯不透明版本；当前未实测此项收益 |
| 地面血 carrier | 预通道声明，discard/scissor | 与空中血滴不同，不能直接同批改 |
| 脚步/死亡烟雾 | Sprite3D opaque prepass，正常检查深度；池上限 72 | 有透明淡出，直接不透明会变样；先查同时可见数量、覆盖面积 |
| 家具碎屑 | StandardMaterial3D 从生成起 ALPHA；最后 0.4 秒才淡出 | 候选：前段不透明，末段透明；需排除材质变体切换带来的峰值 |
| 人物/家具/门/特殊单位独立描边 | 检查但不写入；部分自定义 DEPTH | 多数保持现状，写入可能干扰本体/后续效果；关闭测试会穿墙 |
| 无人机枪口闪光/星形 | 加法混合，检查但不写入 | 保留叠加语义，不建议为深度统一而改 |
| 受击半透明光晕 | 检查但不写入，自定义 DEPTH | 保留，防止光晕深度遮住人物本体 |
| 接触阴影 | 半透明，检查但不写入 | 保留；优化应查面积/数量，而非只改深度开关 |
| 室内飘尘 | discard，无 ALPHA 输出，但显式不写深度；MultiMesh | 可做专项 A/B，但像素覆盖小，预期优先级低；不等于免费 |
| 玻璃 | 真半透明，窗玻璃声明 alpha prepass | 不能直接不透明；低透明度预通道是否有效需按实际阈值和 renderer 测试 |
| 墙/门半调避让 | 多个 shader 检查但不写入，并输出遮挡避让 alpha | 与实心地板不同，不能整类替换成不透明 |
| 调色板、色散、UI 等 CanvasItem 后处理 | 不参与世界 3D 物体深度写入 | 更改世界深度策略不能消除这些全屏处理开销 |

无人机金属/机器人面板虽然写有 `blend_mix, depth_draw_always`，但未输出 ALPHA，不应仅凭 blend_mix 认定为昂贵透明效果。正式 carrier 的 `no_depth_test=false`；发现的 `true` 在房间 debug marker 上，而不是普通战斗效果。

## 实测：地板透明队列 vs 当前不透明队列

- RTX 5070 Ti，Godot 4.7.1 Compatibility，实际 Main 进入正式楼层。
- 输出 1280×720；冻结同一楼层及相机，只替换 11 个地板材质 shader；纹理、反射参数保留。
- 三轮交替次序，单段预热 45 帧、记录 150 帧；900 个计时样本，计时区间不读回截图。
- 最小化后台 force_draw、关闭 vsync / 限帧；不是前台玩家实际交互帧率，也不是峰值战斗测试。

| 轮次 | 当前整体帧中位 ms | 旧透明地板 ms | 当前世界 GPU 中位 ms | 旧世界 GPU ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 6.801 | 6.875 | 2.351 | 2.581 |
| 2（反向次序） | 6.883 | 6.808 | 2.411 | 2.573 |
| 3 | 6.799 | 6.823 | 2.301 | 2.291 |

三轮中位数的平均：整体约 6.828 vs 6.835 ms，相差约 0.008 ms，可视为本范围内没有可确认的整体提速。世界 GPU 平均约 2.354 vs 2.482 ms，前两轮略降、第三轮反向 0.010 ms，不足以承诺固定百分比收益。绘制调用数三轮均为 762，没有减少。

测试正常完成，但退出仍有已有的两张 GL texture 未释放与 RenderingServer 析构顺序错误；没有借此次调查修改这些问题，也不宣称无警告。

## 下一步优先级

1. 空中血滴纯不透明 A/B：高血量峰值、相同随机种子、正常光照与遮挡下测量，并核对 GPU Camera 输出。
2. 碎屑前段不透明 A/B：集中破坏场景，特别比较首次材质切换和 P99，不能只比较平均值。
3. 子弹 scissor/prepass 专项：保留像素轮廓、参考平面及前景遮挡；确认 GPU 实际收益才接入。
4. 烟雾、玻璃、柔和描边保持，除非专项证据证明有可见面积/数量问题。

不建议全局关闭深度测试，或为所有透明效果强制写深度。深度测试能拒绝被遮挡片元；真正成本还取决于透明重叠、draw call、光照及 capture viewport。

官方依据：[Spatial shaders](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)、[GPU optimization](https://docs.godotengine.org/en/latest/tutorials/performance/gpu_optimization.html)。文档用于解释术语与通用机制，项目数值来自上述本机测试。
