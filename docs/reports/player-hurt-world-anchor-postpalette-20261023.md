# 受伤反馈修正：世界锚点与调色后屏幕冲击 · 2026-10-23

## 修正结果

### 文字和星星不再跟随玩家

原实现绘制时每帧读取玩家当前躯干位置，实际做成了跟随。现只在受伤事件发生时记录原始世界位置、摄像机平面方向和像素/世界单位换算。

每次受伤独立保留自己的位置、文字、时间与六颗星星；文字从原受伤位置上浮，星星从原位置散开、旋转并带下落弧线。玩家离开不改变这些记录，镜头移动只重新投影其世界位置，不将它们钉在屏幕上。清晰 HUD 仅负责最终绘制，不再决定粒子的跟随目标。

反馈最长约 0.85 秒，最多同时保留四组；新的受伤不会立即抹掉前一组。中文仍为“好痛！”“我丢！”“哎哟！”“疼啊！”，连续不重复。伤害、无敌、击退及操作规则不改。

### RGB 色散和暗角在 Palette 之后

处理顺序改为：世界 → 原有 Palette（层 18）→ 显式复制调色后的画面 → 受伤冲击（层 19）→ 独立清晰 HUD。

原实现层 17 位于调色前，且两次屏幕读取没有明确刷新中间结果，不能保证屏幕效果串接正确。现加入只在冲击期间启用的 BackBufferCopy，后续色散和暗角不再被 Palette 映射。Godot 的屏幕读取规则见[官方说明](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html)。

屏幕效果改为约 0.30 秒的全世界画面桶形/波纹冲击、径向 RGB 分离和边缘暗化，迅速衰减恢复，不是先前很弱的局部位移。屏幕抖动关闭时禁用画面形变，RGB 色散与暗角仍可显示。HUD、准星、交互文字、菜单不参与该屏幕处理；平时禁用额外画面复制。

NPC 靠近气泡规则及对话正文不再扩展改动。

## 实际画面验收

`player_hurt_camera_test` 从实际 Main 进入接待区及正式随机游戏，使用 RTX 5070 Ti、1280×720 最小化窗口、静音 Dummy 和隔离存档。

本次不只检查 shader 参数：对同一受伤时刻的世界最终图像分别关闭/开启冲击，采样比较结果如下（固定本次生成场景，不代表所有地图）：

- RGB 平均绝对差：0.08855。
- 边缘区域 RGB 总和比：开启/关闭 = 0.63191，最终画面确实暗化。
- 强红/绿分离采样数：关闭为 0，开启为 2025；说明彩边在 Palette 后保留，没有重新压回蓝色系。
- 根 HUD 的独立颜色探针像素前后完全相同，屏幕冲击所在视口仍是世界视口。

动态记录使用真实移动输入，检查玩家已走开超过 16 游戏像素，原组反馈仍保留受伤世界锚点；同时检查镜头平移能重新投影固定的文字世界位置。
