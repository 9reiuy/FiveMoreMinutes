**结论：收下独立试验交付，N2 保留为待试玩的视觉候选；尚不判为最终美术定稿或性能通过，正式游戏不接入。** 下方第一轮退回记录保留为历史。

顾问本轮实际查看了 N/N2 无窗大开间、N2 窗边房间与相邻走廊 Camera PNG，读取功能结果、亮度解释、逐帧灯组交接记录、本轮性能记录及冻结报告，并对照清单核验 23 个关键交付文件的 SHA-256，零不一致。没有重跑游戏/GPU，没有把视频文件解码成功等同于亲自完整观看或玩法可读性验收。

- **照明覆盖有改善**：无窗大开间由中央光岛扩展到两侧工位，右侧桌体和右下通路明显更清楚。窗边仍有局部入射光，走廊有连续亮区；整体仍偏冷暗，暂不宣称已达到用户心中的正常办公照度。最终明暗取舍应结合独立试玩确认，而不是依据平均像素亮度自动通过。
- **室内/室外职责继续分离**：N2 使用原有两处灯具位置，一盏投影主灯和一盏补光；没有统一提高环境底光。顾问直接核验 N 与 N2 的仅室外光 PNG 文件字节完全一致，支持本轮没有改变该窗边机位的室外受光。屋顶及封窗依据沿用第一轮，不重复宣称已验证所有房间。
- **交接证据范围明确**：33 项结果零失败。原生过门记录含 255 个采样，房间 7→4，12 个采样存在新旧灯组重叠，室内阴影灯峰值为 2；执行报告给出 0.42 秒淡变。它支持该门的渐变交接，不保证连续多门或所有种子没有跳亮。
- **性能未通过**：两次 N2 混合战斗 P50 为 26.500 / 29.712 ms，1238/1247 帧超 16.667 ms，最慢 1374.954 ms。同时本轮 N 对照 P50 从 17.839 漂移至 28.276 ms，背景 GPU 端点 9%→26%。不能把 N2 的全部慢帧或相邻差值直接认定为新增灯光的纯成本，也不能将本独立样本结果用于推翻用户已经验证的正式精简灯光修复。
- **范围保持独立**：启动器指向 R1 的 project 与独立 user_data。执行者冻结检查报告记录 8339 个 R1 输入无变化、旧 N 输入无变化；顾问本轮没有重复全量散列扫描。没有发起正式集成。

## 第一轮验收与返修（历史）

2026-11-04。已收到渲染聊天的 READY_FOR_REVIEW 回报，查看了有窗房间和无窗大开间的 A/N 实际 Camera PNG，读取功能结果、遮挡解释、配对统计与范围审计。没有重跑 GPU。

## 结论：部分通过，原聊天定向返修

屋顶与窗光的空间关系已有可复查证据，夜间外部环境也明显压暗。但 **N 的无窗大开间仅中央一片亮区，周边工位、家具下部和通路过暗，尚未满足用户“楼层有顶，但一般都有类似办公室的灯光”的要求**。因此不把本版作为最终夜间办公室照明交付，不要求用户先认可明显不足的室内照明覆盖。

本次只退回原“5MinMore渲染管线”，不再向其他聊天派单。正式游戏保持现状。

## 已成立与未成立的证据

- 功能结果共 34 项，失败 0；其中包含灯光分离、屋顶/封窗、原生门及实际过门、重建和退出。
- 临时移除屋顶后选区 27,771 像素变化，恢复可回到原画面；封窗后相关区域室外光差异下降 96.4%，室内灯仍有效。认可为该诊断房间的屋顶/开口验证，不外推所有房间。
- N 有窗房间的昼夜区分已比 A 明确；柜体、角色附近局部照明和反射保留。
- N 无窗大开间呈现单一中央光斑，大片周边近黑。当前“每室最多选一盏灯”的选择已经限制了画面目标。
- 性能仍未通过：混合 N 的 P50 14.63 ms、P95 21.76 ms、P99 38.62 ms，最慢 532.24 ms，335/1250 帧超过 16.667 ms。背景 GPU 端点为 9% 与 34%，不得将单轮差值当作纯候选成本或精确证明更快。
- 这是独立重负载试验；用户确认正式精简灯光版的尖峰已解决这一状态不变。没有正式接入。

## 返修 R1

**只补正常办公照明覆盖，不推翻已验证的屋顶/窗洞逻辑。** 保留本轮 A/B/C/N 截图、视频与原始计时，后续候选/证据用 R1 或 N2 名称，不覆盖旧报告证据。

1. 按现有办公室灯具/灯带的布局组织室内照明，让大开间的主要工位与连接通路都可读，避免一盏圆形光岛承担整间办公室。光源方向和开启效果要能对应实际灯具位置。
2. 可以采用少量投影主灯配合灯具位置关联的低成本分组照明，但不要为了填黑恢复每灯动态投影，也不要统一拉高整层环境光或给家具/地面加自发光。
3. 保留暗角、家具接触阴影与室外较暗层次；夜间办公室可以被顶灯照亮，不以全屋近黑来表达夜晚。室内灯关闭后仍要与仅有外部窗光区分。
4. 大开间、当前有窗房间、相邻房间分别给同机位 A/N/N2 对照，正常速度片段包含通路/工位、换房、角色与敌人的可辨认性；检查换房时选灯是否突然全屋跳亮或跳暗。
5. 使用与改动相称的功能检查和匹配负载性能对照。保留既有 34 项中与照明覆盖和换房有关的约束；若改动屋顶/窗光则重验对应项。记录实际光源/阴影数量及运行期间的背景条件，不用历史失败数据冒充本次结果。

目标是“一眼能读懂这是正常办公灯照明的封顶夜间楼层”，同时保留外部环境光通过窗洞进入的逻辑。实际 Camera 画面优先于灯数量或某组参数。完成后一次回报顾问，再由顾问集中通知用户。
