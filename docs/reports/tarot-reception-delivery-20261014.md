# 塔罗入口大厅改造交付

2026-10-15 更正：本报告原先将基础接待区材质描述为最终接待区地板，验证范围不足。正式楼层另有美术覆盖层。本轮已复用该覆盖层的大理石纹理、材质和铺贴规则，并修正夜景、办公桌及共享电梯门面。最新结果以 `tarot-reception-revision-20261015.md` 为准；以下保留首次交付记录。

按已确认的参考图布局改造抽塔罗所在的独立入口大厅：主厅 26×16 格、入口 8×4 格；三个相连前台，唯一现有 NPC 位于左工位；左上三部电梯，仅最左侧 1 号可进入。五组休息沙发、两张茶几、深蓝地毯、五条常开闸机通道、十二组绿植，以及空工位、收纳柜、壁灯、导视牌和桌面细节已接入。

地板共享正式楼层接待区的 `approved_room/reception` 材质，保留角色尺度、正式透视摄像机及 40° FOV。大厅使用局部配色，避免全局 16 色滤镜把绿植改成蓝灰色；没有修改玩家保存的设置。正式进入楼层后，显示仍遵从原有调色设置，此切换已在实际 Main 流程中检查。

## 复用与边界

沿用现有前台、电梯、沙发、茶几、办公椅、工作台和收纳柜资产。新增静态闸机、叶片、导视和建筑细节按 8 格空间块及材质合并绘制，使用共享像素材质。闸机只给机柱保留碰撞，开放通道没有玻璃阻挡。塔罗、NPC、伤害、楼层生成及电梯转换规则没有扩展。

核心文件：`dream_3d_reception_room.gd` 负责场景布局和已有流程；`tarot_reception_dressing.gd` 负责家具与装饰构建；显示包装器仅增加按场景保留局部配色的门控。

## 验证

相关逻辑脚本最终均通过，所有完成运行的退出码为 0：

- `tarot_reception_layout_test`：35 条检查，五条闸机实际碰撞通道、至少三格中央通路、柜台与电梯可达、阻挡家具碰撞、唯一 NPC、三个前台和电梯、十二组绿植、共享地板材质。
- `test_reception_scene`：布局、玩家安全大厅能力、碰撞、提示和电梯转换信号。
- `test_reception_room_assets`、`test_reception_interaction_range`：资产与 NPC 交互。
- `test_tarot_system`、`test_tarot_draw_system`、`test_tarot_ui_system`：现有塔罗系统回归。

旧测试中尺寸坐标按本次批准布局更新；旧 NPC 提示断言 `E 交谈` 改为已有实际返回的 `[E] 交谈`，远离柜台后的提示检查等待其现有 0.12 秒淡出。没有为旧断言恢复旧布局或修改提示规则。中间失败记录保留。

正式 Main 入口 GPU 验证 `verified_delivery`：17 条检查全部通过。使用普通数字移动按键组合行走，经闸机、休息区、左侧柜台；正常对话选项信号打开三张塔罗牌，普通卡片选择信号完成选择并存储结果；随后用电梯 E 输入进入实际正式楼层。没有通过手动修改塔罗结果或直接跳转楼层代替流程。最终录制有 212 张逐帧 Camera PNG，窗口全程最小化，独立执行，无子智能体。

## 渲染记录

RTX 5070 Ti / Compatibility / 输出 1920×1080；正式世界仍为项目默认的 640×360 像素渲染尺寸，再放大输出。

| 场景／取景 | 绘制调用中位数 | 说明 |
|---|---:|---|
| 原始大厅入口 | 161 | 旧布局与原始照明，历史基线 |
| 新大厅，四级方向阴影 | 1223 | 初版额外阴影开销较高 |
| 新大厅，相同取景，单级阴影 | 466 | 减少约 62%，保留实际阴影 |
| 最终录制，鼠标取景与前述不同 | 551 | 不与上面进行直接增减百分比比较 |

最终入口固定视点采样 120 个渲染帧：世界视口的 CPU 渲染时间中位数约 **0.637ms**，GPU 渲染时间中位数约 **0.437ms**，GPU P99 约 **0.879ms**。使用引擎视口渲染计时接口，包含该视口渲染；不包含全部游戏 CPU、根画面合成或帧率限制等待，不能据此声称完整稳定 60 FPS。

初始采样的 `Performance.TIME_PROCESS` 包含未刷新的初始化值，未用于性能结论；原始报告保留。首次无隔离用户目录启动有引擎启动崩溃，隔离目录与 Compatibility 后完成验证。退出时仍有既有纹理 RID／RenderingServer 清理诊断，未在本次改造中处理。
