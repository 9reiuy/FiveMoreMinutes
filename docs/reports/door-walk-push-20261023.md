# 玩家走动推门修复

## 原因及修改

玩家 `_push_rigid_props` 曾将地图局部像素坐标直接除以 32 当作全局 3D 接触点，同时未旋转推力方向。正式地图旋转时，这与门的真实铰链坐标系不一致，可能产生错误力矩，继而触发防夹刹停。

新增门自身的 `request_walk_push`，由其负责最近接触点、地图到世界坐标及方向转换；玩家传入碰撞中心和碰撞法线方向，不再手工构造错误世界坐标。沿用现有滑动碰撞触发，不扫描所有门、不建立第二套碰撞，也无需 E。

普通被动推门速度上限由 1.1 调为 2.0 rad/s（适用于现有被动摆动路径）；战斗上限、门血量、材质和破碎逻辑不变。延迟回正、防夹检查及落闩保持。

## 验证

- `door_walk_push_live_test.gd`：实际 Main、正式随机楼层重建后，通过正常移动 Input actions 持续向门行走，不直接调用推门接口、不按 E。两侧均通过，最大开角约 66.309°/70.088°，健康保持满值；4 项检查通过。
- 最终实际 GPU Camera 图片已查看：`.runtime/door_walk_push_20261023/side_1_30.png`，楼层、门、角色均可见。原始报告位于同目录 `report.json`。
- `door_return_motion_test.gd` 20 项通过。
- `physical_door_hinge_cutaway_test.gd` 22 项通过，含防夹、回正、踢门强度和碰撞同步。
- 不宣称覆盖所有布局/家具堵门情况，亦非性能测试；上轮已有两项 AI 路由失败本轮未扩大修复。

测试首次遇到工程中 `muzzle_smoke.gd` 的既有类型推断编译错误，仅将局部 `body` 明确声明为 Vector3，未修改烟雾算法；修正后重新运行实际 GPU 推门测试通过。最终仍有已有 GL texture/RenderingServer 析构退出警告；Headless 回归也有资源释放警告，不宣称全工程无错误。
