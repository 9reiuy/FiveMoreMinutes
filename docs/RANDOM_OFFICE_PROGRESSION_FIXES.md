# 随机办公楼：跨层清理、接待入口与目标引导

## 本轮实现

- 楼层所有权统一覆盖掉落武器、血迹、发射器、碎片、弹丸、显示桥与临时提示。跨层暂存停止运行及碰撞，成功后销毁；生成失败恢复原节点、拓扑与运行状态。楼层令牌拒绝旧层延迟生成。玩家与玩家显示保持跨层存活。
- 五种随机轮廓的出口房间采用安全接待组合。外墙电梯门直接通向接待区，中央通路保留；前台、等候沙发与茶几按接待用途摆放，禁止生成敌人。固定样板未调整布局。
- 接待区不再被旧“电梯房间排除”规则移除地板、顶灯或地图轮廓显示。此次运行截图发现并修复了这个问题。
- 开放办公室只有与走廊共享的边界全开；与其他功能房间的边界保留真实墙与合法门洞。
- 3D 命中保留伤害计算、暴击和反馈，但不生成伤害/暴击文字。换弹文字持续为“正在换弹”，结束或取消清除；换枪名称提示仍保留。
- 轿厢禁攻与手部显示解耦；空手时保留双拳与原精灵，不创建可见几何体。
- 清晰屏幕空间引导：每层恢复控制后计时，暂停/锁定/加载不计时；30 秒后标记存活敌人，卡片掉落后只标卡，拾取后只标电梯。红色敌人、金色卡片、青色空心电梯箭头使用不同图案；屏幕外目标沿显示区域边缘分层排列，墙不隐藏引导。

## 画面与动态证据

`res://.runtime/progression_fixes/` 保存实际 1920×1080 正式摄像机截图：

- `entry_reception_*`：接待出口与等候组合。
- `enemy_arrows_*`、`enemy_head_arrow_*`：屏幕边缘及头顶的红色箭头。
- `reloading_*`：“正在换弹”。
- `badge_arrow_*`、`elevator_arrow_*`：金色卡片与青色电梯箭头。
- 上述各组覆盖像素化开/关与 Palette 关闭/方案 1，手电关闭。
- `enemy_arrows_resized.png`：1366×768；运行检查箭头仍在实际显示区域内。
- `cab_empty_hands.png`：独立轿厢双拳。捕获持续更新至轿厢内角色显示稳定，不以切场景首帧空捕获作为验收图。
- `progression_muted.mp4`：进门、独立轿厢加载、出门到下一层的静音片段；该视频为逐帧记录后 20fps 合成，不用于帧耗时测量。

画面检查确认上述场景显示与文字/箭头清晰，接待区中央路线未被家具占用。截图中的敌人头顶示例使用测试摆位，录制入口为应用显示包装器加正式随机楼层。没有保存本轮修改前同机位基线，因此不声称已提供完整前后对照。密集标记与计时边界主要由自动检查验证；长时间真实交火、多窗口尺寸和所有种子的动态画面尚未逐一人工游玩验收。

## 工程与限制

本轮相关文件差异检查通过。整个脏工作区的差异检查仍报告已有的 `scenes/ui/dream_hud.tscn:86` 末尾空行，未修改该无关文件。

运行有本机证书库读取、Wacom 配置读取与着色器缓存写入警告；编辑器设置因用户目录权限不能保存。部分测试退出仍报告 ObjectDB/资源未释放警告，不能把退出码 0 等同于已排除所有泄漏。本轮三层楼层所属对象检查通过，但全工程退出泄漏仍未完成审计。

没有修改摄像机、楼层旋转、战斗数值、家具美术或旧 2D Dream 规则。尚未重新做性能基准，不能据本轮录制推断帧耗时或中档设备性能。
