# 血迹合并尖峰优化（2026-10-07）

## 实际慢帧依据

命中反馈池接入后重新读取真实运行数据：`.runtime/post_feedback_engine_collector.log`、`post_feedback_engine_summary.json`、`post_feedback_engine_frames.jsonl`、`post_feedback_engine_game.log`。预热 10 秒、采样 60 秒，RTX 5070 Ti、Compatibility、2560×1440 输出 / 640×360 世界视口、像素化及 Palette 1，静音。

## 改动契约

- 每次同步合并尝试读取当前源、目标坐标及内容，只准备一次像素并集，原先外部预检查和吸收内部再次栅格化造成的 6 次栅格化降至 2 次。
- 已压实为 `PIXEL_CELL` 的地面像素直接执行原有两个变换和原有取整，不再为每个像素分配单元素偏移数组。
- 仅复用本次操作结果，不跨帧缓存；开关门、坐标/缩放变化、追加血滴、生命周期及楼层令牌仍在下一次尝试重新读取。
- 原有房间/楼层/源对象限制、墙体检测、108px 合并边界、8192 像素上限、三面包围小孔填补及内容版本更新规则不变。
- 血色、数量、喷洒及扩散曲线、捕获范围和摄像机不变。没有通过降低血量、移除阴影或减少敌人获得收益。

`test_legacy_ground_merge` 仅用于恢复旧的重复计算对照，正常游戏默认不启用。

## 正常交火

`.runtime/blood_merge_normal_combat_ab.log` 记录正式楼层旧 / 新 / 旧对照。须同时检查敌方实际开火量、射手数量及十秒分段负载，再决定是否允许整体帧耗时收益结论。未达到持续 60 FPS 时保留明确的未完成状态。

本轮实测旧 / 新 / 旧中位 19.671 / 17.621 / 17.729 ms，P95 30.127 / 28.266 / 25.730 ms；敌方开火 363 / 293 / 326 次，实际射手 3 / 4 / 3 名，玩家 419 / 422 / 422 次。粗粒度匹配门槛通过（293/363 > 0.8），退出 0；但新组末段仅 8 名存活敌人，旧组 10 名，十秒射击分布和死亡进程亦不同。新组 P95 并未优于第二个旧组，**不认定整体帧耗时提升**，也不据此宣称 60 FPS。保留本改动的依据为同步合并本身的明显计算下降及等价性，而非挑选有利的整局数据。
