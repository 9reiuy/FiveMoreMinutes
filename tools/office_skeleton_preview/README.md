# 四骨架随机白盒

SVG 设计工具、独立 Godot 试玩入口，以及正式游戏的原生四骨架生成器。单层平面，无楼梯或新增门禁玩法。

## 正式游戏接入

正式 `Dream3D_RandomDungeon.tscn` 已启用 `office_skeleton_world_base.gd`，在游戏内部由 `office_skeleton_generator.gd` 生成任意种子的新楼层。A1/B2/C3/V3 在重试前各以 25% 概率选定，建筑外轮廓直接由骨架地格形成，不套旧五轮廓、不循环 40 份 JSON、运行和导出均不依赖 Node。

设计规则保存在预加载的 `office_skeleton_rules.gd` 中，不是地图数据库。每个候选按实际家具旋转占地重新验证三格通路；同一种骨架最多重试 64 次，失败明确返回失败，沿用现有跨层回滚，不偷换骨架或删除核心家具。

14×10 接待、紧凑走廊、可选吸烟室、嵌套房间、成组家具与连续玻璃均保留。固定样板自动走原实现；关闭 `use_native_office_skeletons` 可回到保留的五轮廓生成器。旧 2D 不接入。当前接待流程、工牌、电梯、摄像机、地图角度和战斗规则未改。

布局适配和连续玻璃已抽为正式/试玩共享实现。正式入口不含预览控制面板，不读取预览 JSON。验证结果见 `VALIDATION_FORMAL.md`。

## 独立试玩

从项目根目录运行 `./tools/run_office_skeleton_playable.ps1`，默认静音启动。
也可在 Godot 中运行 `scenes/dream/preview/OfficeSkeletonPreview.tscn`。
F1–F4 切换四骨架，F5/F6 切换随附种子 1001–1010；40 份布局均来自同一个白盒生成器，不保存正式进度。
指定新种子：`./tools/run_office_skeleton_playable.ps1 -Type V3 -Seed 2007`。启动前由 Node 编译该种子的四骨架 JSON，运行时只读取数据，不启动 Node 子进程；可用 `-NodePath` 指定 Node。
主战办公室—走廊边界保留宽开放口，剩余长边使用连续可破玻璃，转角留短实墙；其他功能房间的墙不自动移除。
试玩使用现有 Camera、地图角度、家具目录、战斗与电梯实现。按真实地格导入非矩形房间，不使用矩形包围盒重建地板；不伪造样板身份。
接待为 14×10，白盒中的电梯符号不生成地板或轿厢，仅在接待外墙创建电梯门。内嵌经理室最小 10×11，以满足实际家具的三格通路验证。

## 使用

从项目根目录执行：

```powershell
./tools/run_office_skeleton_preview.ps1
./tools/run_office_skeleton_preview.ps1 -Type V3 -Seed 2007
./tools/run_office_skeleton_preview.ps1 -Count 10 -Seed 3001 -Output '自选输出目录'
```

默认每类 10 张，共 40 张 SVG、布局 JSON、index.html 图库和 report.json。
打开输出目录的 index.html，点击地图查看完整 SVG。同骨架同种子输出完全一致。
Node.js 可通过 -NodePath 指定；生成器只依赖标准库，不安装依赖、不运行游戏或声音。

## 四个契约

- A1：中央交火区、环廊；接待两侧出口；小房间链回到环廊；另一侧经财务区侧入深部。
- B2：西战区→中间连接→东战区→深部；西侧小房间绕回西厅；东厅侧路经休息与机房换角度进入深部。
- C3：接待→主战区→横向过渡→深部；左侧小房间路线接过渡区；右侧长后勤直接侧入深部。
- V3：主战区→枢纽→深部；会议室路线回接枢纽；长后勤侧入深部。

## 随机层级（V3：紧凑走廊、壁挂布景与吸烟室）

普通侧廊实际宽 3–4 格，主要走廊宽 4–5 格；仅局部交火枢纽宽 6–8 格。宽度按实际地格和分段覆盖验证，不仅修改标签。
吸烟室按种子随机出现，每层最多一间，通过一扇门连接侧廊或后勤通道，不在必经路线中；包含成组长椅、烟灰桶、外窗及壁挂标识。
走廊布景为壁挂告示牌、消防箱、管线和门牌，避开门窗。本轮不添加打印机、清洁柜等落地布景，不侵占净通道。

可变宽高的空间带定义不均匀房间组。固定骨架连接、变化尺寸与门洞、嵌套房间角落、兼容功能房型、家具组合位置、整体镜像。
安全接待室的数据严格为 14×10、140 地格。锁定相应空间带确保左右前后仍对接，不是只修改 SVG 比例或尺寸标签。
接待台、工作椅和等候沙发／矮桌为固定组合，中央三格净空；电梯示意居中对接。
所有墙边界来自真实地格所有权。嵌套房间从外室地板中扣除，只通过外室的单一门洞进入。
先为门预留两格家具净空，再放功能组；每次整组放置检查各门口之间的三格通路。最后按家具实际占地重新寻找三格路径，不再预留一条穿过房间中央的旧路径后向空隙撒家具。
工位为平行排列的双桌双椅组；会议桌六椅整体变换；档案柜／机柜为中间留通道的双列；休息室两组沙发共用一张茶几；茶水间连续操作带与朝桌餐椅分组。
虚框标识功能组，短箭头标出家具朝向。每个家具记录 group/member/target；镜像同步变换座椅朝向与对应桌面目标。
仅随机整组布局，不允许组内独立撒点；必要组合放不下则重试候选，不删除其核心成员。重复工位和附属柜可减少。
核心家具放不下就重试整个候选，不删除核心家具或回退旧网格布局。
玻璃不用于默认连通计算；完整玻璃按实墙，标青色以表示可破窗侧攻意图。

## 验证

```powershell
node --test tools/office_skeleton_preview/generator.test.mjs
```

检查 40 个种子、重复生成一致性、骨架差异、镜像、房间与敌人可达、三格路线、门口净空、嵌套入口及核心家具保留。
新增固定 14×10、家具模板完整变换、会议六椅朝向、平行工位、一张共用茶几检查，以及单件散移／反向椅子／错误接待尺寸的负例。
增加走廊实际宽度及覆盖、吸烟室数量与单入口、非必经支线、外窗、壁挂布景合法性及负坐标镜像检查；连续玻璃与开放入口另有检查，共 17 项生成器测试。
负例包含路线堵塞、嵌套门移除、外部家具及接待区敌人。
